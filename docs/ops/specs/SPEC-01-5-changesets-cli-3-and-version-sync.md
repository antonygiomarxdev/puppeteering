# SPEC-01-5: Changesets cli 3, private package tags, and the plugin version sync

Status: Draft
Rests on: ../../requests/REQ-11-changesets-and-scriptorium-install.md

## Summary

The release action reads a file the changesets CLI writes (`CHANGESETS_OUTPUT`). The pinned cli 2.31.1 does not write it; cli 3.0.3 does (checked in its dist/index.mjs). So: move `@changesets/cli` to ^3, opt private packages in to versions and tags (puppet-teams is `private: true`), and keep `.claude-plugin/plugin.json` equal to `package.json` after `changeset version` with a `version` script. First of two release runs.

Last change: 2026-11-21, drafted

## Tests first
D-24, D-29 and D-32, by the tester, in `mods/puppet-teams/hooks/release-version.test.js` (carries `covers: ops/REQ-11/D-32`). Cases: the `package.json` range for `@changesets/cli` starts at major 3 or more; the lock entry `node_modules/@changesets/cli` has version major 3 or more; `config.json` has `privatePackages.version` and `.tag` true; `scripts['release:version']` starts with `changeset version`; on a temp copy of `package.json` and `plugin.json` with the package version set to 9.9.9, running the part of `scripts['release:version']` after `&&` makes `plugin.json` version 9.9.9 (it fails before the script exists).

## Build
`npm install --save-dev @changesets/cli@^3` writes the range and the lock. The `release:version` script is one line: `changeset version && node -e "const f='mods/puppet-teams/.claude-plugin/plugin.json',p=require('./mods/puppet-teams/package.json'),m=JSON.parse(require('fs').readFileSync(f));m.version=p.version;require('fs').writeFileSync(f,JSON.stringify(m,null,2)+'\n')"`. Smallest standard way: the action runs `version-script`, and changesets documents running extra steps after `changeset version` there. The script is not named `version` because npm runs a script of that name during `npm version`. Precondition, not Done: `npm install` (network); Node 22 or newer, which cli 3 requires (`engines`: "^22.11 || ^24 || >=26").
