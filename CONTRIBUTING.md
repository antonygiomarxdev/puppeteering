# Contributing

Thanks for being here. This guide gets better when people run it on real work and report what happened.

## Ways to help

| You have | Do this |
| --- | --- |
| A rule that failed you | Open a [field report](../../issues/new?template=field-report.yml). This helps most |
| Something that worked, with what you ran | Open a field report too |
| A claim that disagrees with the official docs | Open a [docs mismatch](../../issues/new?template=docs-mismatch.yml) |
| A question, or an idea to talk through | Use [Discussions](../../discussions) if enabled, or open a blank issue |
| A typo or a broken link | Send a pull request directly |

## Your first contribution

1. Run the [quick start](README.md#quick-start) on a project of yours, even a small one.
2. Note one thing the guide got wrong, left out, or made harder than it should be.
3. Open a field report. That is a real contribution; no pull request needed.

## Changing the guide

1. Fork, and branch from `main`.
2. Change the rule, and add the run that shows it to [`LESSONS.md`](LESSONS.md) in the same commit.
3. Open a pull request, using the template.

**What a good change has:**

- **Evidence.** What you ran, what happened, what you changed. A rule from a real run beats a rule that sounds right.
- **A source for what a tool does.** Link the [official page](REFERENCES.md). Mark what you only observed as observed.
- **Honesty about limits.** Say what you did not measure.
- **Short sentences, and nothing private.** No customer data, secrets or internal project details in examples.

Keep the guide about running teams of agents. General prompting tips belong elsewhere.

Agent-written contributions are welcome, of course. You are still the one vouching for them: read the diff.
